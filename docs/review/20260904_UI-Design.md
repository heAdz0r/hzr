Date: 2026-09-04. Source: `fbf204d48704160407e3f06035ac32b9cf0bc67a`.

The user explicitly authorized immediate UI implementation through a subagent. This approval covers the design-composition skill's implementation gate. No previous PRD was used. Scope is the existing Vue visualizer and public dashboard data contract; no daemon changes, deployment, or invented savings metrics.

## Product objective

An operator should identify the selected workspace, understand what the economy numbers prove, spot coverage gaps, inspect recent session operations, and reach component diagnostics without scrolling through a marketing page. Full-task savings remain unproven unless supported by task/provider evidence.

## Twelve-module audit

| Module | Current / problem | Target and severity |
| --- | --- | --- |
| M1 Signifiers and grouping | One long page mixes fleet, project, provider and session scope; project selection is buried | Persistent scope selector and four clearly selected navigation sections; HIGH |
| M2 Hierarchy | A 520px hero precedes useful evidence; graphs precede economy | Compact header, evidence summary first, component detail in its own section; HIGH |
| M3 Grid and space | Marketing spacing and dense nested cards make scanning slow | 4/8/12/16/24/32px spacing, max-width 1440px, cards 4→2→1 columns; HIGH |
| M4 Typography | Hero and metric scale overwhelm diagnostic labels | System sans, six dashboard sizes 12/14/16/18/20/24px, tabular numeric values; MEDIUM |
| M5 Semantic palette | Amber brand and estimated values compete with status | Keep ember brand; green only for positive deltas, amber for gaps, red for regressions; labels accompany colors; HIGH |
| M6 Dark mode | Existing dark surfaces are usable but decorative gradients compete with data | Neutral dark base, brighter elevated surfaces, subtle dividers, no decorative glow in new components; MEDIUM |
| M7 Light-mode shadows | Product is dark-only | No light-theme expansion; preserve supported mode; no new dark shadows; not applicable |
| M8 Icons | Existing AppIcon provides consistency | Reuse 16/20px icons; no extra icon dependency; no unlabeled primary actions; LOW |
| M9 Buttons | Several controls have states but navigation is absent | 44px minimum primary touch targets, hover/press/focus, gray disabled, refresh busy label; MEDIUM |
| M10 Inputs and feedback | Search exists, but recent operations cannot be filtered; pagination error is screen-reader-only | Route/agent/session filters, visible result count and reset, visible load error and retry; HIGH |
| M11 Interaction | Copy fallback always announces success even if copy fails; refresh has limited visible confirmation | Truthful copy result, visible refresh status, skeleton/error states, reduced-motion support; HIGH |
| M12 Images and overlays | Background hero image is decorative and heavily obscured | Remove marketing art from functional header; no text over photography; not applicable after change |

## Implementation plan

1. Compact dashboard shell with Overview, Projects, Memory & index, System navigation and direct workspace selection.
2. Evidence summary derived solely from existing local_activity/provider_receipts: estimated net reduction, output flow, recorded operations, uncovered operations and explicit absence of whole-task proof.
3. Recent activity filters by route, agent and session; filtered counts explicitly represent the bounded recent snapshot.
4. Session economics exposes output evidence before optional pricing assumptions; global data moved into disclosures.
5. Responsive and accessible interactions, visible error feedback and truthful clipboard fallback.
6. Run Vue typecheck, production build and Bun tests. Inspect actual desktop/mobile rendering if a browser is available; distinguish fixture checks from live API checks.

## Deferred by contract

Historical session listing, configurable time windows, per-operation expand/retry cost, total provider-billed savings, hook completeness and task-quality comparisons require backend evidence. The UI must not fabricate these fields or imply that a managed route proves useful savings.
