# PRD: HZR 0.10.0 — корректность и честная экономия по итогам внешней оценки

Дата: 2026-09-25. Основание: внешний отчёт «Экспорт сессии: оценка HZR и RTK для galleon/dhcr»
(Claude Fable 5.1, репозиторий dhcr, HZR 0.9.13 `1d3bcb7`, upstream RTK v0.50.0). Все пункты ниже
воспроизведены локально на 0.9.13 (`~/.local/share/hzr/current`, fork `0.44.1-fork.1`), если не
помечено иначе.

Решения владельца (2026-09-25): managed-блок ужать до ≤2,5 КБ, нативные Read/Edit/Write по
умолчанию; из upstream — точечный порт (без rebase); релиз 0.10.0 с тегом и публикацией.

## 1. Введение

Внешний агент прогнал HZR и upstream RTK на Go-репозитории и заключил: HZR «не внедрять»,
выгода RTK ≈1–1,5% входных токенов. Часть выводов верна и указывает на реальные дефекты, часть —
артефакт методики. Этот релиз исправляет всё подтверждённое, добавляет найденные при проверке
дефекты, которых в отчёте нет, и делает учёт экономии честным.

## 2. Критический разбор отчёта

### 2.2 Неверно или завышено

- **«Форк вырезает комментарии при чтении»** — отчёт вызывал `rtk read FILE` напрямую. Хук
  переписывает `cat -n` → `rtk read -n` (без потерь) и `cat` → первые 400 строк точного текста с
  командой восстановления; комментарии сохраняются (проверено на `adapter.rs`). Реальная, другая
  проблема: `rtk read -n` на **5% больше** `cat -n` из-за разделителя `│` (3 байта UTF-8) — см. N5.
- **Форк мерили отдельным бинарником**, не через маршрут HZR (хук/`hzr exec`). Для R1–R4 это не
  меняет вывода (дефекты в фильтрах), но цифры «HZR vs upstream» не отражают полный маршрут.
- **Реплей исключил `git diff` целиком** (0 реплеев, 26 пропусков), а в итоговой арифметике взяты
  3–10% при измеренных 88% на `HEAD~5`. Оценка по `git diff` смещена вниз; с учётом потолка 30K
  истинное значение неизвестно. Итог «≈1–1,5% входных токенов» для профиля «чтения через
  `sed`/`cat` = 37% Bash-байт» при этом правдоподобен — и это главный стратегический вывод:
  фильтры Bash-вывода не двигают стоимость, когда вывод — точные чтения файлов; постоянная часть
  контекста (наш managed-блок) весит сопоставимо.
- **Зрелость** (звёзды, 54 релиза за 7 недель) — сигнал процесса, не дефект; вне рамок релиза.
- **«−105348%» на `go_test_green`** — реальный дефект R1, но число раздуто красным деревом
  (`tmp/review/...` в модуле пользователя).
- Вердикт «не внедрять в dhcr» опирается в основном на интеграционные конфликты (симлинк, запрет
  shell-записей, H2-линтер AGENTS.md) — для их репо обоснован; context plan/память не измерялись.

## 3. Цели

- G1: Ни одна перезапись не меняет смысл команды (N1–N3) — ноль известных случаев «прочитан
  другой файл/сломан синтаксис».
- G2: Фильтры go/golangci/find/diff/read не хуже upstream v0.50.0 на матрице отчёта и без потерь
  без явной команды восстановления.
- G3: Постоянная нагрузка HZR на ход ≤2,5 КБ (managed-блок) и без дублей в SessionStart.
- G4: Учёт экономии не превышает то, что хост реально показал бы модели.
- G5: HZR не мусорит в чужих репозиториях (`.rtk-lock`, `.codex/config.toml`) и не отказывает на
  типовом симлинке `CLAUDE.md -> AGENTS.md`.
- G6: Документация честно говорит об Ollama, egress делегирования и методике бенчмарка.

## 4. User stories

### US-001: Перезапись чтений сохраняет путь целиком (N1)
**Description:** Как агент, я хочу, чтобы `sed -n`, `head`, `tail`, `nl -ba`, `cat … | head` с
путём вида `$VAR/x`, `${VAR}/x` читали тот же файл, что и оригинал.

**Acceptance Criteria:**
- [ ] В лексере fork-core есть хелпер спанов shell-слов (смежные токены без пробела = одно слово).
- [ ] `rewrite_line_range`, пайп `cat X | head/tail/cat` и `sqlite3`-перезапись берут путь по
  спану слова, а не по последнему/N-му токену.
- [ ] Тесты: `sed -n 1,5p $U/a.rs` → `rtk read $U/a.rs --from 1 --to 5`; `head -5 $HOME/a.rs`;
  `cat $U/a.rs | head -5` → `rtk read $U/a.rs --max-lines 5`.
- [ ] `cargo test` fork-core зелёный.

### US-002: Многофайловый `cat` не ломается (N2)
**Acceptance Criteria:**
- [ ] `cat a b` не переписывается в `rtk read` (остаётся tracked proxy/raw) — либо читается
  корректно; тест на отсутствие ошибки.

### US-003: Proxy-маршрут сохраняет шелл хоста (N3)
**Acceptance Criteria:**
- [ ] Хук Claude Code строит `CanonicalCommand` с шеллом хоста: `$SHELL`, если это bash/zsh и
  исполняемый; иначе `/bin/bash`, если есть; иначе `/bin/sh`.
- [ ] `diff <(echo a) <(echo b)` через хук исполняется без syntax error (тест на уровне
  hzr-exec/hook_runner + ручная проверка).
- [ ] `scripts/smoke-install.sh` обновлён и зелёный (память «smoke-install gates hook behaviour»).

### US-004: Guard различает сигнал провала и содержимое (N4, R3)
**Acceptance Criteria:**
- [ ] Для выводов-содержимого (find, ls, tree, grep/rg, read, wc, git log/show/diff/status, diff)
  guard проверяет только пустоту, раздувание и машинный протокол, без regex «error/fail».
- [ ] Тест: `find` по дереву с `error.rs` за пределами капа отдаёт сгруппированный результат + хинт.
- [ ] Тестовые/линт-раннеры сохраняют текущую защиту (`guard_exit`, `looks_failed`).

### US-005: `go test` на Go ≥1.24 (R1, N8) — порт из upstream
**Acceptance Criteria:**
- [ ] `GoTestEvent` знает `ImportPath`/`FailedBuild`; build-fail, package-level fail (timeout,
  panic) попадают в сводку и счётчик провалов.
- [ ] Самовнедрённый `-json` не считается машинным протоколом (guard получает raw без
  protocol-проверки, если пользователь не передал `-json`).
- [ ] `-bench…` не получает `-json`.
- [ ] Регрессионный тест на NDJSON из go1.25 с build fail + test fail: вывод ≤ 600 Б, содержит
  ошибку компиляции и имя упавшего теста.

### US-006: `golangci-lint` v1 и v2 (R2) — порт из upstream
**Acceptance Criteria:**
- [ ] Определение мажорной версии (`golangci-lint --version`, с/без префикса `v`).
- [ ] v2: `--output.json.path stdout`; v1: `--out-format=json`; пользовательский флаг формата →
  без инъекции.
- [ ] Сбой парсинга JSON → вывод raw (stdout+stderr), а не «JSON parse failed».
- [ ] Тесты парсинга версии и фолбэка.

### US-007: `go vet`, `git status` компактнее (порт из upstream)
**Acceptance Criteria:**
- [ ] `go vet` → «Go vet: N issues» c нумерованным списком (формат upstream).
- [ ] `git status` без эмодзи: `* branch...upstream` + porcelain-строки (`XY path`).
- [ ] Существующие тесты обновлены, новые — на формат.

### US-008: `git diff`/`git show` без немых потерь (R4)
**Acceptance Criteria:**
- [ ] Hunk до 100 строк, ведущий контекст ≤3 строк, полный заголовок `@@ … @@ fn`.
- [ ] При любом усечении — заметка по hunk и финальная строка с командой восстановления
  `HZR_RAW_FIDELITY=1 HZR_RAW_FIDELITY_REASON=full_patch hzr exec run '<git diff …>'`.
- [ ] Тесты: контекст сохраняется, усечение всегда сопровождается командой восстановления.

### US-009: `read -n` не больше `cat -n` (N5)
**Acceptance Criteria:**
- [ ] Нумерация `N\t` с шириной по максимальному номеру строки (без `│`).
- [ ] Тест: `rtk read -n` ≤ `cat -n` по байтам на файле >1000 строк.

### US-010: Честный baseline экономии (R11)
**Acceptance Criteria:**
- [ ] `record_receipt`: `baseline` и `delivered` ограничены потолком видимого хосту вывода —
  `BASH_MAX_OUTPUT_LENGTH`, если задан, иначе 30 000 символов; `HZR_HOST_OUTPUT_CEILING=0`
  отключает потолок.
- [ ] Юнит-тест: raw 625 000 Б, delivered 16 000 Б → baseline = 7 500 токенов.
- [ ] CHANGELOG явно говорит, что исторические цифры экономии были завышены на больших выводах.

### US-011: Компактный managed-блок (R5, N7)
**Acceptance Criteria:**
- [ ] Блок ≤2 500 байт для Claude и Codex; тест-пин на размер обновлён.
- [ ] Содержит: одну строку назначения, короткую таблицу маршрутов (exec run, read
  `--outline`/диапазоны, search, context plan, memory, raw recovery), правило «нативные
  Read/Edit/Write остаются по умолчанию», указатель на HZR.md.
- [ ] Удалено: дубли MCP-таблицы (есть в схемах), абзацы про codec-экономику, TDD-абзац (есть в
  скилле), длинные абзацы хуков. Строка `hzr write` — опционально для batch/CAS.
- [ ] SessionStart-уведомление codec удалено или сокращено до ≤120 Б без дублирования блока.
- [ ] `contracts/agent-capabilities.json` и `integrations/claude-code/hzr-awareness.md` согласованы.

### US-012: Безопасные симлинки инструкций (R6)
**Acceptance Criteria:**
- [ ] Obsolete-цель без managed-блока не валидируется на запись и не трогается.
- [ ] Финальный компонент-симлинк разрешается: запись идёт в канонический файл, если он внутри
  корня рабочего дерева (project/local scope) или принадлежит текущему пользователю (global).
- [ ] Две цели, разрешающиеся в один файл (`CLAUDE.md -> AGENTS.md`), пишутся один раз.
- [ ] Симлинк наружу репозитория по-прежнему отклоняется (тест).

### US-013: Не мусорить в чужих репозиториях (R7, N6)
**Acceptance Criteria:**
- [ ] Лок записи fork-core живёт в каталоге пользователя (`$RTK_TEE_DIR/../locks` или
  `dirs::cache_dir()/rtk/locks`), имя = sha256 канонического пути; в рабочем дереве файлов не
  создаётся (тест).
- [ ] Два закоммиченных `*.rtk-lock` удалены из git.
- [ ] Проектный `.codex/config.toml` пишется на SessionStart только если у пользователя есть
  Codex (`~/.codex` существует) и добавляется в `.git/info/exclude`, если не отслеживается git.

### US-014: Честная документация и диагностика (R8, R9, R10)
**Acceptance Criteria:**
- [ ] README/HZR.md: семантический поиск требует Ollama (эндпоинт, модель), без него —
  лексический фолбэк.
- [ ] `hzr doctor`: проба Ollama (HTTP `GET /api/tags`, таймаут ≤1 с) и явная строка
  «semantic: lexical fallback» при недоступности.
- [ ] README/HZR.md «Frontier planning»: явное предупреждение — инструкции репозитория,
  контекст-план, результаты `hzr_read`/`hzr_exec` уходят выбранному провайдеру.
- [ ] Бенчмарк README перезапущен против upstream v0.50.0 на эквивалентной точности; строка
  `--outline` помечена как иная точность или вынесена отдельно.

## 5. Функциональные требования

- FR-1: Перезапись никогда не меняет путь-аргумент; путь = исходный текст shell-слова.
- FR-2: Команды с несколькими файлами для `cat` не переводятся в однофайловый `rtk read`.
- FR-3: Proxy-исполнение использует шелл хоста (bash/zsh), а не `/bin/sh`.
- FR-4: Guard «потеря провала» применяется только к раннерам с exit-семантикой.
- FR-5: Любое самовнедрённое изменение формата (`-json`, `--output.json.path`) не активирует
  protocol-фолбэк.
- FR-6: Любое усечение выводит команду точного восстановления.
- FR-7: Baseline и delivered в квитанциях ограничены потолком хоста.
- FR-8: Managed-блок ≤2 500 байт.
- FR-9: Запись и SessionStart не создают неотслеживаемых файлов в рабочем дереве без исключения.
- FR-10: Doctor различает «семантика готова» и «лексический фолбэк».

## 6. Non-Goals

- Полный rebase форка на upstream v0.50.0 (решение владельца: точечный порт).
- Изменение семантики `hzr write` и MCP-инструментов.
- Бандлинг Ollama или смена провайдера эмбеддингов по умолчанию.
- Индексация «всех открытых репозиториев» на SessionStart — поведение по дизайну, не меняем.
- Замена statusLine, процесс релизов, маркетинговые метрики.
- Дедупликация повторных чтений неизменённых файлов (перспективно, отдельный PRD).

## 7. Технические соображения

- Правки fork-core требуют `scripts/refresh-current-engine.sh` (дайджесты `CURRENT_SHA256SUMS`,
  `CURRENT_ENGINE.toml`, `engines.lock.toml`) — только вычислять, не переписывать руками.
- Версия форка `0.44.1-fork.1` → `0.44.1-fork.2`: `Cargo.toml` форка, `PINNED_RTK_VERSION`,
  `engines.lock.toml`, `FORK_PARITY.md`.
- Изменения хука → `scripts/smoke-install.sh` локально до тега.
- Гейты: `cargo fmt --check`, `clippy -D warnings`, `cargo test --workspace --all-targets`,
  тесты fork-core, `scripts/complete-gate.sh`.
- Общий рабочий каталог: коммитить только явные пути (не `git add -A`).

## 8. Метрики успеха

- Матрица отчёта (14 кейсов + find/ls/wc/grep) на Go ≥1.24: форк не хуже upstream v0.50.0 ни в
  одном кейсе с эквивалентной точностью; `go test` red ≤ upstream; `golangci-lint` v2 даёт сводку.
- Ноль перезаписей, меняющих путь, в наборе из ≥10 форм с переменными.
- Managed-блок: 6 593 → ≤2 500 байт (−62%) на каждом ходе каждой сессии.
- Квитанции: baseline одной команды ≤ 7 500 токенов при потолке 30 000.

## 9. Открытые вопросы
