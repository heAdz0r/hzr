# HZR ← upstream RTK v0.50.0: выборочная синхронизация fork-core — PRD

Статус: **реализовано 2026-09-26** (fork-core `0.50.0-fork.1`, изменения не закоммичены). §14 — что сделано
и где реализация отличается от плана.
Владелец: HZR control plane
HZR: 0.10.0 (`8ec5954`), fork-core `rtk 0.44.1-fork.1`
Upstream: `rtk-ai/rtk` tag `v0.50.0` (`1d87b8e719ce0a50c223cd93ca64dd16921f9aec`, 2026-09-24)
Предыдущая синхронизация: [`PRD_HZR_UPSTREAM_RTK_SYNC_0_4_7.md`](PRD_HZR_UPSTREAM_RTK_SYNC_0_4_7.md)
(0.5.0, upstream `develop` @ `f8d636d`) и точечный порт в 0.10.0
([`PRD_HZR_0_10_0_EXTERNAL_EVALUATION.md`](PRD_HZR_0_10_0_EXTERNAL_EVALUATION.md)).

Это не merge. Деревья расходятся структурно (upstream `src/{core,cmds/<lang>,hooks}` против
плоского `src/*.rs` у нас), поэтому каждый пункт — повторная реализация в нашем файле со своими
тестами. Цифры экономии upstream приведены как upstream их заявил; измерениями HZR они не являются.

## 1. Итог

Между `f8d636d` (что уже взято в 0.5.0) и `v0.50.0` upstream выпустил 475 коммитов без merge;
402 из них по существу (без chore/docs/ci/benchmark). Из 0.44.1..0.50.0 уже есть у нас: lossy-декодирование
потока, `sudo` без перезаписи, приватные файлы данных, модель аргументов `git log`,
`restore_double_dash`, `QuoteScan`, bounded search, exit-code guard, `ignore_dirs`, кап `find` и
подсказка через tee, сокращённые tee-слаги, `pass_through_if_args`, `jsonpack` для `gh api`
(0.5.0), а также `go test` / `golangci-lint` v1+v2 / `go vet` / `git status` /
`compact_diff` (0.10.0).

Выводы, которые определяют этот PRD:

1. **Пять фильтров сейчас выдают ответ, отличный от нативной команды. Всё воспроизведено на
   установленном движке** (`~/.local/share/hzr/current/engines/rtk`, §3). Хук направляет эти
   команды туда по умолчанию: `diff`, `grep -m/-l/-t`, `gh pr checks`, `find` по несуществующему
   пути, `head`/`tail` на не-UTF-8 и CRLF-файлах. Upstream исправил каждый случай в 0.46–0.50.
2. **Самый серьёзный — `rtk diff`.** Если файлы различаются только изменёнными строками,
   он печатает оба файла целиком и выходит с кодом 0, хотя нативный `diff` выходит с кодом 1.
   Агент, который проверяет равенство через `diff a b && …`, получает ложный «успех».
3. **Стек владельца — bun + React, а fork не знает `bun.lock`/`bun.lockb`.** `bunx tsc` превращается в
   `rtk tsc`, а тот запускает `npx`, а не bunx. Upstream 0.48 добавил поддержку Bun/Deno и правило
   «запускать инструмент тем раннером, который назвал пользователь».
4. **Новые модули upstream** (`ctest`, `sqlfluff`, `ast-grep`, `mvnd`, `phpt`, recall store,
   хосты Codex/Trae/OMP, телеметрия, Windows code pages) — это расширение покрытия, а не дефекты.
   По умолчанию не берём (§7–§8).

Рекомендуемый объём для **HZR 0.11.0 / fork-core `0.50.0-fork.1`**: блок P0 (US-001…US-006) +
блок P1 (US-007…US-012) + бамп версии (US-018). P2 — по отдельной отметке.

## 2. Метод и воспроизводимость

```bash
git clone --filter=blob:none https://github.com/rtk-ai/rtk.git rtk-up && cd rtk-up
git log --no-merges --oneline f8d636d..v0.50.0 | wc -l          # 475
git diff --stat f8d636d v0.50.0 -- src                           # 355 файлов, +70k/−12k (0.44.1..)
```

- **Инвентаризация:** журнал коммитов `f8d636d..v0.50.0`, сгруппированный по scope, плюс
  upstream `CHANGELOG.md` 0.44.2…0.50.0.
- **Наличие символов:** grep по `fork-core/rtk/src` на ключевые символы каждого изменения
  (`arg_tokenizer`, `retriever`, `PipelineSafety`, `SIG_IGN`, `is_fully_anchored`, `bun.lock`, …).
- **Поведение:** `hzr exec rewrite '<cmd>'` показывает, куда хук направляет команду. Затем
  побайтовое сравнение нативной команды и переписанной (`od -c | md5`) на фикстурах в
  scratchpad. Пункт, который не удалось воспроизвести, помечен **`verify`** и в план не входит.

## 4. Цели

- **G1 (верность):** ни одна команда, которую хук переписывает, не меняет stdout или exit code
  относительно нативной, кроме задокументированного сжатия с командой точного восстановления.
  Кейсы E1–E12 закрыты регрессионными тестами.
- **G2 (стек):** Bun- и Deno-проекты получают фильтрацию, и инструменты запускаются тем раннером,
  который назвал пользователь.
- **G3 (устойчивость):** прерывание сигналом не теряет уже захваченный вывод; stderr инструмента
  не пропадает в фильтрах, которые разбирают только stdout.
- **G4 (идентичность):** версия fork-core `0.50.0-fork.1`, identity current-engine пересчитана,
  а FORK_PARITY явно перечисляет, что из v0.50.0 **не** взято.

## 5. User stories

Общие критерии для каждой истории: `cargo fmt --check`, `clippy -D warnings`, полный
`cargo test`, `scripts/verify-fork-core.sh --test` зелёные; в коде есть ссылка на upstream-коммит;
тест воспроизводит соответствующий кейс E<n> и падает до исправления.

### P0 — верность вывода (всё воспроизведено)

#### US-001: `rtk diff` — настоящий diff вместо дампа файлов (E1–E3)
**Описание:** как агент, который проверяет изменения через `diff`, я хочу видеть сами различия
и нативный exit code, чтобы `diff a b && …` не давал ложного успеха.

**Upstream:** `0cb34ac`, `428af61` (вердикт по байтам), `d4239ec` (выравнивание Myers/LCS,
hunk'и), `f2780d4`, `1246ce3`, `d1a0d9c` (классический fallback `NcM`), `8495176` (baseline =
классический diff, а не склейка файлов), `ca85483`, `ee614e4`…`1b11b52`, `f4495eb`, `9634a9a`,
`27abf4a`, `501dd01`, `8073112` (stdin-режим `condense_unified_diff`: разбор по регионам,
маркеры на колонке 0, строки `++`/`--`, байтовый raw fallback).

**Наше состояние:** [`diff_cmd.rs`](../fork-core/rtk/src/diff_cmd.rs) сравнивает строки
позиционно (`compute_diff`, :102), признаёт файлы одинаковыми при `added == 0 && removed == 0`
(так случается, когда все отличия — `Modified`), обрезает строки до 80 символов и не показывает
больше 50 изменений без команды восстановления, читает файлы через `read_to_string` (падает на
не-UTF-8), никогда не выходит с кодом 1. В stdin-режиме строки `++x`/`--x` теряются, маркеры
сдвигаются на два пробела. Guard `never_worse_content` сравнивает с конкатенацией файлов, поэтому
«отказ» и есть дамп из E1.

**Критерии приёмки:**
- [ ] Вердикт по байтам: при различии только CRLF/LF или последнего EOL файлы не объявляются
  одинаковыми; причина названа; exit 1.
- [ ] Выравнивание Myers: одна вставка = одна вставка (E2 → `0a1`-эквивалент).
- [ ] Exit code как у `diff(1)`: 0 — одинаковые, 1 — разные, 2 — ошибка (нет файла, нет прав).
- [ ] Флаги, которые мы не моделируем (`-u`, `-r`, `-q`, `-w`, `--color`, …), уходят в нативный
  `diff` без `[rtk: parse failed]`. Правило в `rules.rs` сужено или обработка в clap расширена.
- [ ] Baseline для учёта — вывод классического `diff`, а не склейка файлов.
- [ ] Любое усечение заканчивается командой точного восстановления HZR (как `DIFF_RECOVERY_HINT`).
- [ ] В stdin-режиме маркеры на колонке 0, `++`/`--` в теле hunk'а сохраняются, заголовки файлов
  в кавычках декодируются, при неразобранном регионе — побайтовый raw.
- [ ] Не-UTF-8 файлы: байтовое сравнение, без паники и без U+FFFD в выводе.

**Объём:** L (upstream `diff_cmd.rs` +7.5k строк, большая часть — тесты и hg/svn-формы).
Раунды 7–8 для hg/svn — опционально, см. §9.

#### US-002: `grep -m/-l/-t` — нативная семантика (E4, E5)
**Описание:** как агент, я хочу, чтобы `grep -m 1`, `grep -l`, `grep -t` значили то же, что в GNU
grep, чтобы переписанная команда не меняла результат.

**Upstream:** `16228b7`, `4ea0555`, `3b6b812`, `5681008`, `d9a5893`, `eb3f814` (BREAKING 0.47: у
rtk остаются только длинные `--max-len`/`--max`, короткие флаги переходят к движку).

**Наше состояние:** `main.rs:394-404` объявляет `-l` = `max_len`, `-m` = `max`, `-t` = `file_type`,
причём `file_type` в диспетчере отбрасывается (`main.rs:2688`). `-m1` в слитной форме уже работает
верно, `-m 1` раздельно — нет. Наш собственный `grep_cmd.rs` (у upstream аналога нет) проверить
тем же набором.

**Критерии приёмки:**
- [ ] `grep -m 1 P f`, `grep -m1 P f`, `grep -l P f…`, `grep -L`, `grep -c`, `grep -t` — вывод и exit
  code совпадают с нативным (или совпадает множество строк, если применено задокументированное
  группирование).
- [ ] `--max-len`/`--max` работают только в длинной форме; миграция задокументирована в CHANGELOG
  как изменение поведения.
- [ ] Правило в `registry`: у переписанной команды короткие флаги не пересекаются с флагами rtk.

#### US-003: `gh pr checks` — сводка и при упавших checks (E6)
**Описание:** как агент, который ждёт CI, я хочу видеть, какие checks упали, когда `gh` выходит
с кодом 1, — ради этого команду и запускают.

**Upstream:** `ecdf332` (без early exit на failure), `d105227` (каждый bucket: pass / fail /
pending / skipping / cancel, итог сходится с числом строк), `656a864` (dedupe при `--watch`),
`83f87f9` (реальная форма строк gh в тестах).

**Наше состояние:** `gh_cmd.rs:333-343` при ненулевом exit печатает только stderr и выходит;
разбор ищет подстроки `"pass"`/`"fail"` во всей строке (имя job'а `fail-fast-lint` считается как
fail), cancelled и skipped теряются.

**Критерии приёмки:**
- [ ] При exit 1 от упавших checks печатается сводка со списком упавших; exit code 1 сохранён.
- [ ] Разбор по колонке bucket из табличного вывода gh, а не по подстроке в имени.
- [ ] Сумма по bucket'ам = число строк checks; cancelled/skipped показаны.
- [ ] Реальная ошибка gh (нет репозитория, нет авторизации) → stderr без изменений и нативный
  exit code.

#### US-004: `find` — ошибки и пропуски видны (E7, E8)
**Описание:** как агент, я хочу, чтобы `find` по несуществующему пути завершался ошибкой, а
скрытые или gitignored совпадения, которые rtk пропустил, были раскрыты.

**Upstream:** `765b270`, `9cf048a` (отсутствующий путь — как у find; раскрытие пропусков),
`68dc719` (ограниченный учёт, symlinked root, заметка как у `ls`), `5d697b0`, `d3f31dd`, `f614c3c`,
`989f453`, `988f2e3` (диспетчеризация по грамматике find: неизвестные предикаты — сжатый вывод
нативного find).

**Наше состояние:** E7 — пустой вывод с exit 0; E8 — 2 из 4 путей без заметки. Наш фикс
«путь корня как задан» (`7b27089`, PR #10) сохранить.

**Критерии приёмки:**
- [ ] `find <missing>` → stderr find и exit 1, stdout пуст.
- [ ] Если walker пропустил hidden/gitignored совпадения, одна строка раскрывает их число и
  команду, которая покажет их.
- [ ] Предикаты, которые мы не моделируем (`-newer`, `-perm`, `-exec`, `-o`, скобки): вывод
  нативного find, затем сжатие; exit code нативный.
- [ ] Тесты путей корня из PR #10 остаются зелёными.

#### US-005: `head`/`tail` → `rtk read` побайтово верны (E9, E10)
**Описание:** как агент, я хочу, чтобы `head -N`/`tail -N` возвращали ровно те байты, что нативные
утилиты, включая CRLF, отсутствие последнего EOL и не-UTF-8.

**Upstream:** `ed8480f` (`--head-lines` — точное окно; нарезка по смещениям байтов N-го `\n`;
гейт `is_single_file_operand`: `head -n 1 *.rs`, `--help`, `#` не переписываются), `6f4913b`
(окна на не-UTF-8), `0df1d2b` (head читает кусками и останавливается на N-й строке:
`head -n 5 /dev/urandom` возвращается сразу).

**Наше состояние:** E9/E10 воспроизведены. `head` сохраняет CRLF, `tail` — нет. Сноска HZR
`[lines a-b of N]` требует полного чтения файла ради N. **`verify`:** зависает ли
`head -n 5 /dev/urandom` через хук и переписываются ли глоб-операнды.

**Критерии приёмки:**
- [ ] Тело вывода побайтово равно нативному `head`/`tail` на фикстурах: latin-1, CRLF, без EOL,
  пустой файл, `N=0`, `N > строк`.
- [ ] Head не читает дальше N-й строки на нерегулярных источниках (FIFO, `/dev/urandom`).
- [ ] Операнд, который может раскрыться в несколько слов или оказаться опцией, остаётся у
  нативного бинарника.
- [ ] Решение по сноске (см. открытый вопрос Q1) реализовано и покрыто тестом.

#### US-006: `git diff`/`git show` — устойчивость compact-пути (E12)
**Описание:** как агент, я хочу, чтобы compact-путь `git diff`/`git show` не ломался от цвета и
внешних diff-драйверов и отвечал за мою команду, а не за вспомогательную.

**Upstream:** `4a2e58d` (сначала выполняется команда пользователя, и её exit — вердикт; стат-проба
только декорация; ANSI снимается до разбора), `5d3c1e5` (`git show --oneline -p <sha>` печатал
HEAD из-за сдвига индексов; честная заметка о капе `git log -p` через пробу limit+1),
`f126a11` (`--quiet` в `git show` не синоним `-s`), `71fe764` (`-p` в diff/show не обходит compact),
`7272290` (маршрутизация diff/show/log закреплена на реальном git).

**Наше состояние:** `DIFF_HARDENING` (`git.rs:59`) не содержит `--no-color`, поэтому
`color.ui=always` или `--color` ломают разбор (E12). Шаг 3 `run_show` (`git.rs:555`) использует
`git_cmd` без hardening, так что ext-diff и textconv применяются к разбираемому diff.
`run_show` запускает git четыре раза; `--oneline -p` дублирует заголовок. `run_diff` запускает
`--stat` первым и отдаёт его ошибку вместо ошибки команды пользователя.

**Критерии приёмки:**
- [ ] `--no-color` в hardening разбираемых путей + снятие ANSI перед `compact_diff`; E12 даёт
  compact-вывод.
- [ ] Все разбираемые шаги `run_show` идут через `git_diff_cmd`.
- [ ] Команда пользователя выполняется первой; при её ненулевом exit — её stderr и exit code
  побайтово.
- [ ] `git show --oneline -p <sha>`, `git show -U5 <sha>`, `git show -W <sha>` показывают `<sha>`, а
  не HEAD.
- [ ] **`verify`:** есть ли у нас кап `git log -p` с заметкой; если есть — проба limit+1 вместо
  подсчёта заголовков `commit`.

### P1 — устойчивость и стек

#### US-007: сигнал не теряет захваченный вывод
**Описание:** как агент, чью команду прервал таймаут хоста, я хочу получить то, что команда уже
успела вывести, и видеть смерть от сигнала, а не обычный exit code.

**Upstream:** `9900d70` (перехват SIGINT/SIGTERM, пересылка ребёнку, эскалация до SIGKILL, сброс
захваченного вывода), `5b1d523` (после сброса — повторный raise, чтобы вызывающий видел
signal death), `9418aa8` (унаследованный `SIG_IGN` не перетирается).

**Наше состояние:** в [`stream.rs`](../fork-core/rtk/src/stream.rs) нет обработки сигналов
(только `status.signal()` при выходе ребёнка). `CaptureOnly`-фильтры теряют всё при прерывании.

**Критерии приёмки:**
- [ ] Unix: SIGTERM на rtk во время `CaptureOnly` → ребёнок получает SIGTERM, захваченный вывод
  напечатан (raw или отфильтрованный), rtk умирает от того же сигнала (`128+15` у вызывающего).
- [ ] Ребёнок, игнорирующий SIGTERM, добивается SIGKILL за ограниченное время.
- [ ] Если rtk запущен с `SIG_IGN` для SIGINT (nohup/фон), обработчик не ставится.
- [ ] Не-Unix: поведение без изменений.

## 6. Функциональные требования

- FR-1: Для каждой переписанной команды из матрицы §3 stdout совпадает с нативным побайтово
  (или отличается только задокументированным сжатием с командой восстановления), а exit code
  совпадает всегда.
- FR-2: Фильтр не превращает ненулевой exit ребёнка в нулевой и наоборот.
- FR-3: Флаги rtk не затеняют короткие флаги нативного инструмента, в который переписана команда.
- FR-4: Неразобранный вход → нативные байты, без предупреждения `parse failed` в stdout.
- FR-5: Любое усечение выводит команду точного восстановления HZR.
- FR-6: Вывод, пересланный как есть (stderr, raw fallback), учитывается как delivered.
- FR-7: Инструменты JS запускаются тем раннером, который указан в исходной команде; lockfile bun
  распознаётся.
- FR-8: Прерывание сигналом на Unix сбрасывает захваченный вывод и сохраняет signal death.
- FR-9: Дифференциальный harness `scripts/upstream-parity-probe.sh` (новый) воспроизводит
  E1–E14 одной командой и входит в gate релиза.
