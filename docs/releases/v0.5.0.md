# HZR 0.5.0 — the engine stops losing output

Every release so far argued about how much HZR saves. This one is about what it was quietly
throwing away.

`fork-core` was imported from `rtk-ai/rtk` at `v0.44.1` and has developed inside HZR since.
Upstream kept moving: 59 commits and 60 open pull requests later, several of the defects it
fixed were in the shared filter code HZR inherited verbatim and never touched. This release
adopts that work — re-implemented against our own tree, because the two layouts diverged too far
for a merge to be expressible — plus the highest-value unmerged upstream proposals.

Nothing here increases measured savings. One item deliberately reduces them.

## The three that were losing data

**A single non-UTF-8 byte truncated the rest of a command's output.** The reader chained
`BufRead::lines()` with `.map_while(Result::ok)`, and `map_while` stops the iterator at the first
`Err` — so one latin-1 filename, one binary blob in a test log, one stray byte in a compiler
diagnostic discarded *every remaining line of that stream*. The child still exited 0, the filter
ran on a truncated buffer, and the difference was recorded as a saving. Lines are now split on the
raw byte and decoded lossily: the garbled line survives, and so does everything after it.

**`git log --stat` was reformatted instead of passed through.** Flag detection scanned the
argument list without knowing which options take a separate value, so `git log --grep --pretty`
read the search *term* as a format flag, `git log -- -p` lost its pathspec separator to clap, and
`-U5` parsed as `-U` plus a limit. Requests for a raw diff shape — `-p`, `--stat`, `--numstat`,
`--shortstat`, `--raw` — now hand the whole invocation to git untouched, and a closed list of
~30 value-taking options keeps a flag-lookalike value from being read as the flag.

**A multi-line `[[ … ]]` could be split in half.** Bash lets a conditional span lines; the
multiline rewriter treated each line as independent and could rewrite the first half into
something that cannot parse. The four hand-rolled quote-state walkers behind those checks are now
one shared `QuoteScan`. Separately, a lone `\r` is no longer treated as a command separator —
bash runs `git status\rrm -rf ~` as one mangled git command, and splitting it over-segmented the
permission verdict from the command that actually ran.

## HZR no longer inserts itself into `sudo`

`sudo docker ps` was rewritten to `sudo rtk docker ps` — an *asserted* behaviour, with a test
pinning it. The user granted elevation to one binary; HZR added a second. An elevated engine
inherits `RTK_DB_PATH`, the memory DB path and the private PATH/audit directories, all of which
point at a user-owned data root, so it left root-owned `history.db`, `-wal`/`-shm`, tee files and
audit rows that the user could only remove with another `sudo`.

`sudo`, `doas` and `pkexec` prefixes — bare or via an absolute path — now stop the rewrite. The
command runs verbatim and is accounted under a new closed class, `e11_privileged_prefix`, marked
**not avoidable**: it is a deliberate refusal, not something the agent could have phrased better,
and it must not consume the avoidable-bypass budget.

Alongside it, data files are created owner-only rather than chmod-ed after the write, which left
a window where content was readable under a permissive umask. That covers the engine's history
DB and its SQLite siblings, tee output, the telemetry salt and the memory cache — and, on the HZR
side, the ledger database and the daemon runtime directory.

## `gh api` stopped truncating, and got smaller anyway

`gh api` was rendered by a "compact preview" that cut strings past 200 characters and arrays to
five items. The caller could not act on that body and could only recover by re-fetching. It is
replaced by `jsonpack`: a lossless re-encoding that removes only the field names repeated on
every row.

A top-level array of objects becomes a declaration line plus CSV rows — `[N]` declares the row
count so truncation is detectable, `?` marks a nullable column, an empty cell means the key was
absent, a bare `null` means JSON null, and lookalike strings stay quoted so `42` and `"42"` can
never blur. An envelope object stays valid JSON with dense inner arrays rendered as
`{"_cols":…,"_rows":…}` tables.

The reason this is safe to ship is not the encoder. `pack()` **decodes its own output and
requires exact equality with the parsed input before emitting a single byte**; an encoder bug, or
adversarial data that collides with the notation itself, returns the raw bytes unchanged. The
worst case of the feature is the previous behaviour.

`gh <cmd> --json` is a different question — it is exact passthrough today, and packing it emits a
notation the caller did not ask for. That is a product decision, not a bug fix, so it stays
behind `RTK_GH_PACK_JSON=1` / `[gh] pack_json = true` until it has been measured. `--jq` and
`--template` are the caller's own projection and are never touched.

## A search could kill the agent that ran it

Path-based search buffered the engine's entire stdout through `.output()`, then copied it again.
Upstream reports a 30 GB log tree producing 4.6 GB of matches, the engine peaking near 9 GB, and
the *calling agent* being OOM-killed; `| head -N` is no escape, because nothing is written until
the child exits. Capture now goes through the streaming path that already caps retention at
10 MiB and says so when it truncates. The same fix applies to `grep_cmd`, which is HZR's own and
has no upstream counterpart.

## Filters that reported success on failure

A filter that renders an all-green summary next to a non-zero exit turns a failing verification
step into a passing one — which is the one thing a token-efficiency layer must never do. The
never-worse guard is extended from output size to *exit status* across `cargo test`/`nextest`,
`pytest`, `ruff`, `mypy`, `tsc`, `vitest`/`jest`, `go vet`, `go test -json`, `golangci-lint` and
the lint fallback. `prettier --check` additionally reads its file list from stderr, where
prettier has written it since 1.19, instead of discarding every line containing `[warn]` and
reporting "All files formatted correctly" beside exit 1.

## Smaller corrections

- `[filters].ignore_dirs` / `ignore_files` had no readers anywhere in the engine — configured,
  documented, and silently ignored. They now reach the system commands.
- `find` compared its guard against the full match list rather than the plain listing at the same
  cap, so a small capped run cost more tokens than it saved; and a `find` carrying flags the
  engine cannot filter (`-not`, `-exec`) now passes through instead of failing with an error the
  rewrite made impossible to follow.
- `du -s` / `du -d N` are no longer cut to 40 lines. Every row is an independent total, so the cap
  dropped the largest consumers while reporting a confident answer. The TOML filter engine gained
  `pass_through_if_args`, which any of the 59 declarative filters can now use.
- `turbo`, `quarto-render`, `bundle-install`, `gcc`, `spring-boot`, `liquibase` and `ssh` filters
  were over-broad or lossy — `java -jar anything.jar` activated Spring-specific compaction.
- `rtk lint src` read the bare path as a linter name and reported a verdict for a run that never
  happened. Only recognised linter names are treated as linter names now.
- `playwright --reporter list` left `list` behind as a positional test filter, silently running
  the wrong (usually empty) test set.
- `prisma migrate status` counted the *word* "applied" in prose, so a database with pending work
  reported "1 applied, 0 pending" — backwards. It now counts migrations, and falls back to the
  raw text rather than inventing "0 applied, 0 pending".
- `curl` injected a bare `-s`, which silences errors along with the progress bar; `-sS` keeps
  curl's own message. `git commit` preserves `--`, announces its own failure instead of ending on
  a pre-commit hook's `...Passed` line, and `git diff` works again with an external diff driver.
- `npm`/`npx` stream their filtered output instead of retaining it until the child exits, so a
  dev server's readiness line is visible while it is still useful.
- `ls` reports how many noise directories it omitted, `head`/`tail` honour `exclude_commands`,
  and tee recovery-hint filenames collapse long slugs to a short prefix plus hash.
- Informational stderr — notes about commands that *succeeded* — can be suppressed with
  `RTK_QUIET=1` or `[hooks] quiet = true`. Real errors and truncation warnings never are.

## Read this before comparing `hzr stats`

The `git log --stat` fix **reduces** measured savings on those invocations, because passing the
output through unchanged is the correct answer and produces more tokens than mangling it did.
The `gh api` change moves in both directions: it stops discarding content, and removes more
repetition than the old preview did. A ledger delta across this boundary is a change of
behaviour, not a regression, and the two are not separable by the numbers alone.

The evasion panel in `hzr stats` now lists every class that occurred rather than the top ten. The
taxonomy has eleven entries as of this release, and a capped list reads as a complete one.

## Boundaries

- Upstream's measured figures for the search memory fix and the `gh` packing are upstream's,
  taken on their fixtures. They are not reproduced here and are not HZR results.
- Windows console code-page decoding, the upstream streaming-filter framework, and the JVM/.NET/
  PHP/Ruby command suites were reviewed and deliberately not adopted. The reasoning is recorded
  per item in `docs/PRD_HZR_UPSTREAM_RTK_SYNC_0_4_7.md`.
- The fork-core Clippy ratchet stays at 141 inherited warnings. The recorded hash moved because
  the sync edited many of the same files and the ratchet pins each warning's source line; a count
  that had grown would mean new debt, and it did not.
