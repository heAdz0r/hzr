# HZR 0.4.4 — Intent-aware anti-evasion control plane

HZR 0.4.4 makes normalization the cheapest path for agents. Shell wrappers, quoting, absolute
tool paths and simple interpreter disguises are normalized before policy; ambiguous constructs
Ask instead of silently reaching proxy; genuine work without an equivalent route remains allowed
and is typed E10 rather than punished.

The baseline audit is an output-size estimate, not provider billing. In the fresh 0.4.3 window,
`anonymous_bot` delivered 284,686 estimated tokens with 131,705 through bypass routes. Compound
file reads plus one unfiltered blame accounted for 85,070 tokens. This release closes those
specific routes, but it does not claim the seven-day SLO before a full post-release window exists.

## What changed

- A canonical fork-core lexer produces a typed rewrite plan for POSIX shell launchers, environment
  and utility prefixes, quoted ranges and bounded pipelines. The HZR adapter consumes JSON rather
  than parsing human output. Malformed or ambiguous wrappers fail to Ask, not proxy.
- An 85-case executable anti-evasion matrix covers E1–E10, shell depth, quoted `sed`/`nl`, native
  tools, interpreters, temp-log laundering, private-ledger reads, fidelity and genuine E10 work.
- The RAW fidelity hatch now requires a closed compatible reason:
  `binary`, `checksum`, `machine_protocol`, `complete_log`, `full_patch`, or `verbatim_source`.
  Missing, unknown and contradictory reasons Ask before execution. The per-session allowance is
  five operations or 100,000 estimated tokens.
- Native `Read`, `Grep`, `Glob`, `Edit` and `Write` have `observe`, `steer` and `strict` policy
  modes. New installations default to `steer`; legacy upgrades remain `observe` with a doctor
  warning. Allowed native work is accounted as typed E10 without invented savings.
- Privacy-safe policy events record Ask, Deny and Correction separately from command operations.
  Commands, queries, paths, SQL, heredocs, environment values, raw agent IDs and session IDs are
  scrubbed before persistence. Agent attribution uses a per-ledger HMAC pseudonym.
- `hzr stats --evasion` reports bounded E1–E10 and session scorecards. Unbounded
  `stats --json --all` is refused; producer and accounting-policy versions separate current data
  from compatibility history. Read accounting separates source selection from transform overhead.
- Compact routes now include grouped `git blame`, budgeted ordered `read --batch`, SELECT-only
  SQLite, tar listing and bounded remote Docker logs. The existing macOS `ps` formatter now keeps
  complete PIDs and command fields. Generic test/error filters preserve argv and the child's exact
  nonzero exit code, so a compact route cannot turn a failing gate green.
- `hzr init` enables repository-graph indexing and installs managed local `CLAUDE.md` and
  `AGENTS.md` regions while preserving user content. `hzr doctor` reports instruction drift,
  native-policy mode and fidelity allowance. `hzr test` forwards the exact test argv.

## Enforcement boundary

Normalization precedes punishment. A safe equivalent is transparently rewritten; an avoidable or
ambiguous escape receives a named correction or Ask with a replacement. Arbitrary computation,
migrations, code generation and remote shell programs are not heuristically rewritten and are
never penalized merely because HZR lacks an equivalent.

Fidelity is intentionally narrow. Exact bytes are allowed only when the closed reason matches the
operation and no first-class path can preserve that contract. Policy events have zero delivered
tokens and never inflate command or savings totals.

## Upgrade impact

The release command installs a versioned bundle and atomically switches
`~/.local/share/hzr/current`. Refresh workspaces with:

```bash
hzr install --force
hzr init --if-needed
hzr doctor
```

Restart open agent sessions after installation so they reload the current managed contract.

## Verification

The release is gated by:

```bash
cargo fmt --all -- --check
cargo clippy --locked --workspace --all-targets --all-features -- -D warnings
cargo test --locked --workspace --all-targets --all-features
hzr rtk -- test ./scripts/verify-fork-core.sh --test
cd visualizer && bun test && bun run typecheck && bun run build
```

The current fork gate covers 1,874 passing tests, one intentionally ignored test, the immutable
baseline, a 526-file current-engine manifest and the reviewed 141-warning inherited Clippy ratchet.
The 2% avoidable-bypass and 60% per-workspace reduction targets remain a measured seven-day
post-release acceptance window, not a release-time savings claim.
