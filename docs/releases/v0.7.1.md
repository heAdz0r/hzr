# HZR 0.7.1

HZR 0.7.1 is a client-binding safety hotfix. It prevents development smoke state and the last
repository that ran `hzr install` from becoming another project's effective MCP workspace.

## MCP workspace integrity

- Codex's user-level HZR server is now an unpinned dynamic fallback. Each initialized repository
  still owns an exact `.codex/config.toml` pin, while the fallback resolves the root supplied by
  the current client instead of retaining an unrelated repository path.
- A pinned MCP server compares its configured workspace with the single root supplied during
  initialization. A conflict rejects `initialize` before tools are listed, so search, reads, and
  memory calls cannot run in the foreign namespace.
- `init --if-needed` launched from the user home detects that the would-be project config is the
  user-level Codex config and keeps it dynamic instead of pinning it to the home directory.
- Claude Desktop remains an explicit singleton, but ordinary global installation no longer
  retargets a valid selection to whichever repository invoked the installer. Operators select it
  deliberately with `hzr mcp config --client claude-desktop --workspace <dir> --apply`.

## Development configuration containment

- `HZR_ALLOW_DEV_CLIENT_WRITE=1` is no longer sufficient to write a development binary into a
  real user configuration. The destination must also resolve inside the system temporary
  directory, including through macOS's `/var` to `/private/var` alias.
- Existing missing, development-binary, or temporary Claude Desktop selections are repaired to
  the stable installed HZR binary. Valid deliberate selections are preserved.
- Automatic `init --if-needed` and fleet reconciliation now preserve Git-tracked shared
  `AGENTS.md` and `CLAUDE.md` contracts. Cross-workspace audits no longer report those
  repository-owned files as stale, and explicit scope changes remain the only path that can remove
  those managed blocks.

## Upgrade

Install 0.7.1, then reconnect Codex, Claude Code, or Claude Desktop so the client starts the new
stdio process and reloads its registration. Existing indexes, memory, and accounting history are
not migrated or deleted.

HZR 0.7.1 publishes `linux-x64`, `linux-arm64`, and `darwin-arm64` archives plus aggregate
`SHA256SUMS`. The release workflow publishes only after the complete source and bundle gates pass.
