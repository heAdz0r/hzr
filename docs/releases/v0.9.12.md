# HZR 0.9.12

HZR can delegate bounded work to a provider and model selected by each user.
Your chosen Codex or Claude model retains planning, review and final acceptance.

## Configure once

```sh
hzr settings login --provider opencode-go
hzr settings delegation --provider opencode-go --model deepseek-v4.1-flash --enabled true
hzr delegate --file task.md
```

New installations keep delegation disabled. OpenCode GO, OpenRouter and direct
DeepSeek presets support an explicit model, turn limit and timeout. Each user
supplies their own key through a hidden prompt or a private file. Keys never
belong in configuration exports. Disable new workers with
`hzr settings delegation --enabled false`.

The upstream Astra Flash orchestration pattern is adapted to HZR's existing
managed runtime, with preserved MIT provenance. The complete execution runtime
ships in the native bundle. No external Router, Python, npm, pip or extra runtime
download is required.

## See actual delegation

The visualizer's Delegation tab shows exact provider/model, real tool activity,
observed tokens and terminal state. Open the local visualizer with
`?view=delegation` in Codex's browser panel. These are HZR-managed workers;
the panel does not impersonate Codex's native child-agent tree.

Worker completion remains distinct from parent acceptance. Provider-reported
usage is not a measured savings percentage, and forced termination can leave
usage incomplete.

## Reliability and boundaries

Concurrent settings reload under a private update lock. One delegated worker is
allowed per HZR data root. Timeout and cancellation terminate the process group
and write a terminal receipt that cannot be overwritten by a late heartbeat.
Credential reads reject unsafe files; worker requests reject provider redirects.
The real bridge now receives stdin EOF correctly.

File tools retain workspace confinement and shell tools retain HZR policy.
Task scope is not an additional OS sandbox. Delegation must not bypass host
permissions. Live OpenCode GO implementation acceptance passed; live Claude-host
acceptance was unavailable because the local Claude CLI was unauthenticated.
