# HZR 0.9.10

This release makes accounting coverage settle a finished producer on its own, so a transient `▲ LIVE DEGRADED` no longer waits out the day-long abandon TTL.

## Accounting recovery

Completing an accounting context is the definitive signal that its producer is done, so completion now also closes the fork-producer gap the registration opened. A producer that finished inside its pending grace was in flight the whole time and is removed as a settled registration; one that outlived the grace closes as a historical gap. Either way `hzr stats` stops reporting `▲ LIVE DEGRADED` immediately instead of at the abandon TTL.

The Claude Bash hook registers a producer the moment it approves the managed command, but it can still steer that command to a first-class route (`hzr read`) or fall back to raw — neither writes the receipt the correlation expects. The hook now completes such a discarded correlation, closing the orphan's gap at once. An `Ask` that proposes the managed command is left alone: the host may still approve and run it, so its receipts can still arrive.

`hzr doctor --fix` reconciles stale fork-producer registrations once the pending grace has elapsed, not only after the abandon TTL, so an operator can clear a registration left open by an earlier version — for example one opened by a daemon-free command during a daemon restart — without waiting a day. A still-running producer inside the grace is left alone; repair still requires an authenticated, version-compatible daemon health response.

## Known limitation

The engine emits no completion marker for the proxy path, so a hook command that runs through the proxy drains its receipts (closing its gap) while its context file lingers with no completion until the 24-hour abandon TTL retires it. That is directory-growth hygiene, not a coverage state, and remains a candidate follow-up.

## Upgrade

Run `hzr update` to install this release. No new permission rules are installed, monitoring remains opt-in, and all historical accounting evidence is retained.

Verification includes the complete source/fork regression gate and native bundle/install checks.
