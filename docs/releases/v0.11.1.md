# HZR 0.11.1

Semantic search keeps files that editors save atomically, filtered memory recall stops coming
back empty, and `hzr doctor --fix` cleans up after the grepai `.gitignore` edit from #22.

## Semantic index: grepai 0.35.0 → 0.37.0

- A file saved atomically (temporary file + rename — most editors and `hzr write`) was removed
  from the semantic index until the next full scan: 0.35.0 logged `Removed src/ls.rs from
  index` on the rename. 0.37.0 treats it as a modification and re-indexes the file.
- The index is written atomically and recovered if the file is corrupted, an unchanged index is
  no longer rewritten, equal scores are ordered deterministically, and the watcher exits with a
  clear error when file watching fails.
- Indexes built by 0.35.0 are read unchanged and `grepai search --json` keeps its fields. The
  HZR worktree-isolation patch is rebased onto 0.37.0.
- grepai 0.36+ turns on one-result-per-file search in a fresh config, which returned 3 hits for
  `-n 5`. HZR switches it off after initialization, so new and existing workspaces search the
  same way.
- Building grepai from source needs Go 1.25.5.

## Memory recall with a filter

Recall scoped to a project, topic or keyword could return nothing although matching memories
existed: ICM's HTTP `/recall` ranked and cut to the requested count across every project
before filtering, so other projects' memories filled the list and were then discarded. The new
ICM patch `0.10.61-http-recall-filter-headroom.patch` asks the store for up to ten times as
many candidates (at most 200) while a filter is active and cuts after filtering, as ICM's own
MCP recall does. ICM stays at 0.10.61: 0.10.65 fixed this only for its CLI, and its other
changes either need embeddings (off by default in HZR) or break the glibc Linux bundles.

## `hzr doctor --fix` restores the `.gitignore` grepai edited (#22)

Before 0.11.0, `hzr index init` let grepai append `.grepai/` to a tracked `.gitignore`.
`hzr doctor` now reports it, and `hzr doctor --fix` (also the post-upgrade pass over every
workspace) restores the file from HEAD — only when the working copy is HEAD plus exactly that
line. Your own edits and a committed `.grepai/` line are left alone.

## Tests

Init tests whose config names no engine directory now pin an empty one, so an older grepai on
the host `PATH` can no longer fail them.
