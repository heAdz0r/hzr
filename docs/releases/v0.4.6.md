# HZR 0.4.6 — the shadow budget measures something

0.4.5 shipped the enforcement ladder's measurement surface: a Stop scorecard reporting how much
avoidable bypass a session performed, against a shadow budget that would eventually bind. The
number it reported was always zero.

Three layers had to be peeled to reach the cause, and the first two were each mistaken for the
whole of it.

1. The scorecard read a `SessionFeedback` field that no code path ever wrote. Fixed in 0.4.5 by
   reading the ledger instead.
2. The ledger's per-session query was correct, but executed operations carried no session. The
   hook receives the session on stdin; the engine that records the operation is a different
   process and could only learn it from the environment, which nothing set.
3. With the session finally attached, the figure still read zero: the `avoidable` column is
   written from the classification, and the hook forwarded that only on the fidelity path. The
   daemon computed it and returned a bare decision, so the hook could not forward what it never
   received.

0.4.6 closes 2 and 3. `/v1/exec/rewrite` returns the classification with the decision, and the
hook carries both the session and the classification into the process that records the row.

## Boundary

Attribution failures no longer change decisions. For a fidelity request the attribution is a
precondition and a failure is still an Ask; for everything else it is accounting, and accounting
must never turn a working command into a prompt. An approved decision keeps the source and reason
the agent was going to see rather than having them replaced by fidelity wording.

The budget remains measured, not enforced. Its thresholds — 40 avoidable operations and 250,000
avoidable tokens per session — were authored before anything could observe them, and they need one
real shadow window before they are allowed to bind.
