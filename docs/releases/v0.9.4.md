# HZR 0.9.4

This patch removes the permission prompt Claude Code showed on every HZR-routed
command outside `bypassPermissions`, keeps the merge-request link a push
returns, and stops macOS from accumulating duplicate `hzrd` Login Items.

## Claude Code stops asking about every routed command

Outside `bypassPermissions`, the `PreToolUse` hook handed Claude Code the
managed form of each command — a multi-line environment prelude carrying a
per-run correlation id — without a permission decision. Claude Code then
evaluated its allowlist against that script. No `Bash(...)` rule can match it,
so every routed command produced a Yes/No prompt, and the prompt could not offer
a rule that would stop the asking. An operator with a complete allowlist was
asked as often as one with none.

fork-core's typed `rewrite-plan` now reports the verdict of the host's own Bash
rules for the command as the operator wrote it, and the hook acts on that
verdict:

- An allow rule matches: the hook answers `allow` for the managed form. The host
  would have run the original without a prompt, so nothing new is granted.
- No rule matches and the mode prompts (`default`, `acceptEdits`, `plan`): the
  command is left as written. Claude Code prompts for that command, a "don't ask
  again" answer becomes a durable rule, and the next call takes the managed
  route silently. That one run is unfiltered and earns no savings credit.
- Explicit ask and deny rules, `bypassPermissions`, Codex, and HZR's own policy
  answers (opaque shell wrappers, fidelity requests) are unchanged.

Commands with command substitution, backticks or more than one line are left to
the host's judgement even when a rule matches, mirroring the host's own refusal
to prefix-match them.

## `git push` keeps the merge-request link

The push filter reduced a successful push to `ok <ref>` and dropped every
`remote:` line together with the object-count progress. GitLab answers a push
with the merge request it created, or the URL to create one; GitHub prints the
pull-request hint the same way. Those notices now follow the `ok` line:

```
ok feature
remote: View merge request for feature:
remote: https://gitlab.example.com/group/project/-/merge_requests/42
```

Blank rows, `====` decoration and progress rows stay out.

## One `hzrd` in Login Items

macOS no longer accumulates duplicate `hzrd` rows in System Settings > Login
Items, nor re-posts the "hzrd may run in the background" notification on every
release. Bundled binaries carry a stable ad-hoc code-signing identifier
(`dev.headz0r.hzr.hzrd`) instead of the linker's per-build one, so Background
Task Management recognises the upgraded daemon as the same item, and
`hzr daemon service install` re-bootstraps the launchd job only when the
definition changed or the job is not loaded. Rows already left behind disappear
after `sfltool resetbtm` and a re-login.

## Upgrade

Run `hzr update`. The hook and the daemon read the new plan field from the
bundled engine; nothing in Claude permission settings, indexes or historical
accounting is rewritten.

Release archives support Linux x64, Linux ARM64, and macOS ARM64.
