# HZR 0.10.0

An external evaluation measured HZR against upstream RTK v0.50.0 on a Go repository and found
filters that failed on current toolchains, lossy output without recovery and a large per-turn
instruction cost. 0.10.0 fixes each confirmed defect, the correctness bugs found while checking
it, and makes savings accounting honest. Assessment: `docs/PRD_HZR_0_10_0_EXTERNAL_EVALUATION.md`.

## Rewrites keep the command's meaning

- `sed -n 1,5p $DIR/a.rs`, `head -5 $HOME/a.rs` and `cat $DIR/a.rs | head -5` read the file the
  caller named. They used to read `/a.rs` or the directory `$DIR`.
- `cat a b` stays a concatenation instead of becoming a failing single-file read.
- Compound commands proxied through HZR run in the host's bash or zsh, not `/bin/sh`, so
  `<(…)`, `[[` and arrays keep working.

## Filters that work on today's tools

- `go test` on Go 1.24+ summarises compile failures (3,451 → 318 bytes on the repro; the
  evaluated module had printed 5.4 MB of injected NDJSON).
- `golangci-lint` v2 is detected and summarised with the first issues listed verbatim.
- `git diff`/`git show` keep whole hunks, fit the host's 30,000-character window and end any
  truncation with the exact-recovery command.
- `find`, bounded reads and listings no longer fall back to raw output because a file name
  contains "error"; `grep -rn` prints the lossless `rg --heading` shape; `cat -n` is smaller
  than the command it replaces.

## Less overhead on every turn

- The managed instruction block is 1.6 KB instead of 6.7 KB. Native Read/Edit/Write stay the
  default; the SessionStart codec notice is gone.
- Small files are returned whole and range reads report `[lines A-B of N]`, so fewer follow-up
  calls; MCP memory recall returns five compact memories instead of ten complete bodies.

## Honest numbers

Savings are credited only up to the 30,000 characters Claude Code shows the model
(`BASH_MAX_OUTPUT_LENGTH`). On the re-run benchmark, host-visible output is 38% smaller than raw
and 17% smaller than upstream RTK v0.50.0; see
`benchmarks/hzr-vs-rtk-upstream-v0.50.0`. Earlier releases overstated savings on outputs larger
than that window.

## Cleaner machines

`hzr write` no longer leaves `*.rtk-lock` files in repositories, SessionStart writes
`.codex/config.toml` only when Codex is installed (and excludes it from git), symlinked
`CLAUDE.md -> AGENTS.md` repositories install cleanly, and `hzr doctor` probes Ollama, names
ICM's retrieval mode and reports leftover lock files. README and `HZR.md` now state that
semantic search needs Ollama and that delegation sends repository content to the provider.
