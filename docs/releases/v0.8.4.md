# HZR 0.8.4

HZR 0.8.4 fixes two session ROI reporting errors: exact numbered file reads could
appear to increase token usage, and a Claude Code session could be priced using
the configured model when its status line had not recorded the actual model.

## Compare numbered reads with numbered reads

The file reader compared plain source text with output containing the requested
line numbers. It now includes those same line numbers in the baseline, as the
stdin reader already did. Exact numbered reads therefore report zero transform
savings. Output bytes and source coordinates are unchanged; this correction
does not claim that the model receives fewer tokens.

Existing ledger rows are preserved. Historical regressions recorded with the
old comparison are not retroactively recalculated.

## Recover the session model at completion

Stop and SubagentStop can recover the latest matching assistant model from a
bounded 256 KiB tail of the host-supplied session transcript. Other sessions,
user messages, synthetic models, incomplete JSON and symlink transcripts are
excluded. If no usable model is found, the existing status-line/configured
selection remains available. Status-line model capture also runs before the
upstream renderer, so rendering delays cannot postpone that capture.

Public-list estimates remain estimates, not invoices. Actual billed usage is
still unknown without provider receipts, and negative net savings still produce
zero potential savings rather than a session budget.

## Upgrade

Run `hzr update` after the release is published. No configuration or
stored-session migration is required.
