# HZR 0.4.5 — Enforcement that tells the agent what to run

0.4.4 made normalization the cheapest path and closed every routing hole the 0.4.3 audit proved.
It left one gap in the layer the agent actually reads: a construct that could not be normalized
was refused with `fork-core canonical policy requires approval` and nothing else — no class, no
route, no cost. That covered 25 of the 85 acceptance cases. A refusal an agent cannot act on
costs a turn and teaches nothing, which is the failure mode the anti-evasion design exists to
avoid.

0.4.5 is a hotfix for that layer. Routing behavior is unchanged.

## What changed

- Every Ask and Deny names its evasion class and the construct behind it, and prescribes the
  route to use instead. `EvasionClass::construct()` and `EvasionClass::prescription()` are the
  single authority for that wording, so the fork, the daemon and the degraded hook path cannot
  drift apart. Where a managed form exists, the message states what approval will run.
- Ask and Deny now report the running session avoidable-bypass count. Only corrections increment
  it: an E10 Ask is a genuine capability gap and never consumes the budget.
- The acceptance matrix asserts the guidance, not only the verdict. `expect_reason_contains` is
  required for all 31 Ask and Deny cases, the loader refuses an empty expectation, and a gate
  ties each expectation to a prescription the taxonomy emits — so changing the wording without
  changing the matrix fails the build.
- `hzr stats` bypass rows merge on the label they print. `rg`, `grep`, `rgai` and `search` share
  one privacy-safe label, and mapping after grouping listed the same family several times with
  its traffic split; the merged row also stops reporting search as having no first-class route.

## Boundary

A command with no attribution keeps the original wording. Inventing a prescription for an
unclassified construct would put a guess in front of the agent as guidance, which is worse than
a generic message.

An E10 Ask still carries `tier=t2_deny_with_prescription`. The behavior is right — `avoidable` is
false and the fidelity budget is untouched — but the label reads as enforcement against a command
that has no managed route. `EnforcementTier` is persisted in the ledger, so correcting it is a
schema decision rather than a hotfix, and it is tracked as the next item.

## Verification

```bash
cargo fmt --all -- --check
cargo clippy --locked --workspace --all-targets --all-features -- -D warnings
cargo test --locked --workspace --all-targets --all-features
```

The 2% avoidable-bypass and 60% per-workspace reduction targets remain a measured seven-day
post-release acceptance window, not a release-time savings claim. Ledger windows that span the
0.4.3/0.4.4 accounting change are not comparable: current-policy reporting excludes unattributed
legacy rows, so a drop in bypass share across that boundary is a change of denominator.
