# HZR 0.4.2 — Bounded reads and current instructions

HZR 0.4.2 makes response-density policy and instruction freshness executable invariants.

- Ordinary Claude and Codex tasks no longer import or bootstrap the complete `HZR.md`.
- Unbounded `read --level none` falls back to the smart view unless
  `HZR_EXACT_FIDELITY=1` explicitly requires the complete file.
- Semantic/auto search is the discovery route; exact remains available for known literals,
  symbols, errors, keys, and audits.
- New typed ledger dimensions distinguish read/search modes and internal transport from final
  delivery without storing queries, paths, contents, or secrets.
- `hzr init --if-needed` refreshes current managed blocks and retires a delimited legacy RTK
  block that would override the global contract.
- `hzr doctor` remains read-only and now rejects stale policy or conflicting local directives.
- GitHub tag releases are stable and explicitly marked Latest.

The historical audit is intentionally bounded: older ledger rows did not preserve modes. See
[`20260821_exact-full-utilization_High-Critical.md`](../review/20260821_exact-full-utilization_High-Critical.md)
for the lower/upper bounds, acceptance criteria, and accounting limitations. Canonical upgrade
guidance and the complete verification matrix are in the repository-root `RELEASE_NOTES.md`.
