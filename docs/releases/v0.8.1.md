# HZR 0.8.1

Doctor and lifecycle hotfix on top of 0.8.0.

## Root causes

1. **MCP `hzr_doctor` output contract.** 0.8.0 added `readiness` to the doctor report but not to
   the strict MCP output schema, so every `hzr_doctor` call over MCP returned
   `contains unknown property readiness` and no success was confirmed.
2. **Orphaned ICM servers.** Seven `icm serve` processes launched by release install smoke
   fixtures on 2026-09-03 outlived their daemons after the fixtures were deleted. Doctor counted
   them as foreign duplicate owners and, by policy, offered no remedy.
3. **Undrained fork receipts.** Hook rewrites performed while `hzrd` was unavailable ran
   fork-core under a locally generated correlation without registering an accounting context.
   The sweeper only drains journals with a context, so 6531 journals (7644 operations) stayed
   undrained and `accounting` readiness stayed degraded.
4. **Stale fleet registrations.** Nine `hzr-wt-*` worktrees had been deleted; their registrations
   failed `--reconcile-fleet` with "root is absent" on every run.

## Changes

- `hzr_doctor` schema declares `readiness`, `fidelity_reconcile`, `fleet_reconcile` and
  `orphan_cleanup`.
- `foreign.rs` classifies orphans: argv[0] inside an HZR `engines` directory, parent exited, and
  the executable or its `--db` data removed. `hzr doctor --fix` re-reads the PID from `ps`,
  requires the same argv[0] and orphan classification, then sends SIGTERM and, after three
  seconds, SIGKILL. Foreign processes are never signalled.
- ICM patch `0.10.61-exit-with-parent.patch` adds a parent watchdog behind
  `ICM_EXIT_WITH_PARENT_PID`; the supervisor sets it on every spawn. `smoke-install.sh` also
  terminates every engine launched from its fixture on exit.
- The hook registers a `hook_cli` accounting context for daemon-free rewrites. The sweeper
  drains context-less journals older than 600 seconds as project `unattributed`, at most 200 per
  sweep, and quarantines rejected batches as `.rejected` with a `ForkProducer` gap event.
- `--reconcile-fleet` prunes `workspaces/<repository>/<worktree>` for registrations whose root
  was deleted while its parent exists; dry runs report `would_prune`.
- `post_upgrade.rs`: `runtime/reference-state.json` marker, detached
  `hzr doctor --reconcile-fleet --fix --json` launched from `hzr init --if-needed` on a version
  change (not from the installer's `--skip-service` call), foreground run from `hzr update`,
  and the `reference_state` doctor check.

## Verification

Source: `scripts/complete-gate.sh --source` (fmt, clippy `-D warnings`, workspace tests,
fork-core verification). Installation: `hzr release 0.8.1 --force` on darwin-arm64, then
`hzr doctor --reconcile-fleet --fix` against the live fleet of 109 registered workspaces.
