# HZR 0.10.1

`hzr delegate` was run against real tasks and checked against the upstream
astra-flash-orchestrator worker contract. It now finishes them. The read path is lossless
for code, and `hzr doctor --fix` repairs every leftover of earlier versions in existing
repositories, automatically after an upgrade.

## Delegation that finishes the job

On the same bug-fix task, a 0.10.0 worker used all 12 turns re-running one command whose
output it could not read, and ended with "model response is empty". It used 38.8K input,
186K cache-read and 10K output tokens. The 0.10.1 worker finished in 4 turns and 23 s with 8K
input, 17K cache-read and 4K output tokens, and returned a report with verification results.

- Command output reaches the worker as text (it was an array of byte numbers), with the
  caller's `PATH`, so project tools such as `npm`, `cargo` and `go` are found.
- The turn limit is a quota, extended while the worker makes progress, up to five times.
- Every run ends with a report — STATUS, changed paths, verification commands with exit
  codes, risks — written by HZR from the worker's activity if the model wrote none; such
  runs exit 2.
- `hzr delegate` prints the report and one summary line with worker tokens. `--json` is a
  compact object instead of the full event stream (168 KB for a six-second task).

## Reads you can edit from

The default read level no longer strips comments, and it no longer deletes code after a `/*`
inside a string literal. A Markdown document reads as its text instead of a digest.

## Clean repositories, automatically

`hzr doctor --fix` excludes the managed `.grepai` link and an HZR `.codex/config.toml` from
`git status`. It deletes untracked zero-byte `*.rtk-lock` files and refreshes stale managed
blocks. The post-upgrade fleet pass applies the same repair to every registered workspace. A
second run changes nothing.
