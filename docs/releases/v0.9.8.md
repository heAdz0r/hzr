# HZR 0.9.8

This release fixes Claude Bash approval regressions, reconciles stale accounting gaps after a daemon outage, and adds one-command agent onboarding.

## Claude Bash permissions

When HZR cannot confirm permission for the original Bash command, the hook leaves that command unchanged for Claude to evaluate. This includes Auto mode, missing or unknown permission modes, and missing engine verdicts. Accounting environment statements no longer replace the permission surface in those cases.

Confirmed allow rules and explicit bypassPermissions retain managed execution. Explicit ask and deny decisions remain enforced; unfiltered fallback earns no savings credit. No broad shell-wrapper allowlist is required.

## Accounting recovery

A successful daemon rewrite now closes abandoned session gaps across the hook, rewrite, CLI and MCP surfaces. Recovery no longer depends on the new session having previously been degraded.

Run `hzr doctor --fix` to reconcile stale gaps on demand. Repair requires an authenticated, version-compatible daemon health response; it does not report an outage as recovered while the daemon is unavailable. Historical missing-operation counts remain visible. Fork-producer gaps still require receipt reconciliation.

## Agent onboarding

`hzr agents onboard --project <worktree> --agtx-data-dir <store-root>` verifies or installs the observer and enrolls the workspace in one command. Failed observer installation stops before enrollment and preserves configuration. A new board still requires one explicit `hzr agents board` invocation; HZR does not create its store or launch agtx implicitly.

## Upgrade

Run `hzr update` to install this release. No new broad permission rules are installed. Monitoring remains opt-in, and historical accounting evidence is retained.

Verification includes the complete source/fork regression gate and native bundle/install checks. Hook protocol tests cover 35 mode/verdict combinations; they do not constitute a live Claude Desktop UI test.
