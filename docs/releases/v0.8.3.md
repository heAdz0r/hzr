# HZR 0.8.3

Prepared 2026-09-05 on top of 0.8.2; see `CHANGELOG.md` for the itemized list.

## Findings that motivated the release

1. **Build artefacts filled the disk.** On the workstation that develops HZR, `target/debug`
   had grown to 58 GB (79 GB with `fork-core/rtk/target`) on a 460 GB disk with 17 GB free.
   Cargo never removes superseded artefacts: every dependency bump, feature set, RUSTFLAGS or
   toolchain change adds a hashed variant next to the previous one, and with full DWARF for every
   dependency each variant was large. The symptom that surfaced first was unrelated software:
   Telegram Desktop hung for 70–87 s three times that morning and was killed by Jetsam.
2. **`hzrd` write and CPU storms.** macOS resource diagnostics for the daemon on 2026-09-05:
   70 % CPU over 129 s with every sampled frame in `write(2)`, 2.1 GB of file-backed writes over
   ten hours by one daemon instance and 8.6 GB in 27 minutes by the next. The fork directory
   held 18 965 entries: 431 registration contexts (none completed) and about 18 500 `.lock` and
   `.drain.lock` files that nothing had ever removed. The sweeper listed the directory twice per
   second and ran a full drain attempt (lock file, two journal probes, rotation probe) for every
   context, idle or not. A rejected receipt batch of a registered context returned an error every
   second forever, and every error rewrote and fsynced the coverage state.
3. **The coverage state grew by one interval per command.** `accounting-coverage.json` held
   2 071 intervals of which 2 067 were successful commands: a registration was closed on
   recovery instead of removed, so every command became a "historical gap". The 714 KB file was
   rewritten twice per command (registration and recovery).
4. **Abandoned registrations were never retired.** A command the host denied after the hook
   registered it, or a producer that crashed, left its context forever. Registration refuses new
   contexts above 20 000, so accounting would eventually have stopped for every new command.
5. **The approved command carried policy JSON.** The PreToolUse hook returned every rewritten
   command as a script beginning with `export HZR_INTERNAL_EVASION_JSON='{"class":
   "e5_pipeline_or_redirect",…,"avoidable":true,"tier":"t1_named_correction",…}'`, followed by
   the engine environment (`unset RTK_DB_PATH`, a `PATH` prefix, twelve exports) and the
   rewritten command. Claude Code's auto-mode permission classifier evaluates that text, and in
   one session it refused a large share of ordinary commands, including `df -h | tail -1` and
   `cargo clean`, while identical commands passed a moment later. The classification has a
   consumer only after the command ran, so it never needed to be in the command.
6. **`hzr stats` coverage figures did not add up.** One ledger printed "67 daemon-free
   rewrite(s) remain absent historically", "missing accounting rows by producer: hook=0 cli=0
   mcp=0 fork=3" and "6 closed gap interval(s) retained · 3674s missing". The 67 also counted 60
   operations imported from the pre-typed counters and 3 producer gaps; the producer line had no
   column for the `rewrite_daemon` surface (4 operations); the seconds were the duration of the
   closed gaps. The WHERE IT WAS AVOIDED table showed `bypass 4.2K` while OPTIMIZER BYPASS
   showed 4.5K, because 259 explicitly unmeasured passthrough rows have no per-command aggregate.

## Changes

- `Cargo.toml`: `[profile.dev] debug = "line-tables-only"` and
  `[profile.dev.package."*"] debug = false`. Panic locations and backtraces stay readable;
  `CARGO_PROFILE_DEV_DEBUG=2 cargo build` restores full debug info for one build.
- `scripts/target-hygiene.sh`: removes artefacts whose fingerprint was not used for
  `--max-age-days` (default 7) from every `target/**/debug` of both Cargo workspaces, removes
  idle incremental sessions, and runs `cargo clean --profile dev` when a debug directory still
  exceeds `--cap-gb` (default 20). `--dry-run` previews. Release artefacts and
  `target/hzr-component-cache` are never touched. `scripts/complete-gate.sh --source` runs it
  first; `CONTRIBUTING.md` documents it.
- `hzr-exec::accounting`: `remove_accounting_locks(handle)` removes `<journal>.lock`,
  `<failure journal>.lock` and `<journal>.drain.lock`; `accounting_lock_correlation(path)`
  identifies lock files. Lock paths are built by one helper shared with the drain.
- `hzr-daemon::accounting_sweeper`: one directory listing per sweep (`ForkInventory`); a drain
  runs only for correlations that have a receipt or failure journal; completed registrations and
  registrations older than `ABANDONED_CONTEXT_TTL_SECS` (24 h) without receipts are retired
  together with their locks; lock files without context or journal older than the orphan grace
  (600 s) are removed, 500 per sweep; a rejected registered batch is quarantined once as
  `.jsonl.rejected` and recorded as one closed `rejected_receipt_batch` gap; the loop sweeps
  every second while producers are active or receipts drained and every five seconds otherwise.
- `hzr-core::accounting_coverage`: a fork-producer registration recovered inside
  `FORK_PRODUCER_PENDING_GRACE_SECS` is removed instead of closed; intervals written that way by
  earlier versions are pruned on the next write; `with_exclusive_state` rewrites the file only
  when the update reports a change; `ensure_missing` moves `last_failure_at_unix` at most once
  per `REPEATED_FAILURE_REWRITE_SECS` (60 s).
- `hzr-core::accounting_coverage`: `AccountingReceiptContext.evasion` (optional, omitted when
  absent) and `register_with_attribution`; one atomic `write_context` for registration and
  completion.
- `hzr-daemon`: `accounting_sweeper::register_attributed` stores the daemon's classification when
  `exec_rewrite` registers the correlation; `attribute_receipt` copies it onto drained receipts
  that carry none. The `hzr exec run` paths register without one because the execution envelope
  hands the attribution to the engine directly.
- `hzr-cli::hook_runner`: `attach_hook_evasion` exports the attribution only for the T4 fidelity
  hatch; the daemon-free fallback registers with the hook's classification.
- `hzr-exec::adapter`: the engine environment prelude begins with
  `# HZR managed route: engine environment for the command that follows; …`.
- `hzr-cli::stats`: `AccountingCoverage.rewrite_missing_operations` and
  `legacy_missing_operations`; the ACCOUNTING COVERAGE section prints "N operation(s) absent
  from the ledger historically: A before producer classification · B daemon-free rewrite(s) · C
  producer gap(s) [· D undrained receipt(s)]" with A + B + C + D = N, "producer gaps by
  surface: hook= cli= mcp= fork=", and "Ns of closed gap"; the `bypass` subsystem row adds the
  unmeasured passthrough operations so it equals the OPTIMIZER BYPASS count.

## Effect on existing data

- The first write to `accounting-coverage.json` after the upgrade prunes settled registrations.
  Lifetime and per-surface missing-operation totals drop by the number of successful commands
  that earlier versions had counted as gaps; real gaps and open intervals are unchanged.
- Existing lock files are removed over the first sweeps (500 per sweep) once they are older than
  600 s and have neither a context nor a journal.
- Registration contexts older than 24 h without receipts are retired on the first sweep. The
  open gap each of them recorded stays in the coverage state.
- A context written with a classification is not readable by a 0.8.2 daemon (the context type
  denies unknown fields); a downgrade after the upgrade would quarantine such contexts as
  `.invalid` and record them as gaps. The fork-core engine's own tracking rows for hook-approved
  commands no longer carry the classification; the ledger, which `hzr stats` reads, does.

## Verification

`cargo fmt --all --check`, `cargo clippy --locked --workspace --all-targets --all-features --
-D warnings` and `cargo test --locked --all-features -p hzr-core -p hzr-exec -p hzr-daemon`
passed on darwin-arm64 (0 failures). New coverage:
`recovery_inside_the_grace_removes_the_registration_instead_of_closing_a_gap`,
`settled_registrations_written_by_earlier_versions_are_pruned_on_the_next_write`,
`repeated_inspection_refreshes_the_timestamp_at_most_once_a_minute` (hzr-core);
`lock_files_are_removed_on_request_and_identified_by_correlation` (hzr-exec);
`abandoned_registration_is_retired_with_its_locks_without_faking_recovery`,
`stale_lock_files_without_context_or_journal_are_removed`,
`rejected_registered_batch_is_quarantined_once`,
`registration_classification_is_attached_to_unclassified_receipts` (hzr-daemon);
`registration_keeps_the_classification_and_reads_contexts_written_without_one` (hzr-core);
`ordinary_classification_is_not_exported_into_the_approved_command`,
`absent_operations_itemize_into_legacy_rewrite_and_producer_gaps`,
`unmeasured_bypass_operations_count_in_the_bypass_subsystem` (hzr-cli).
`in_flight_producer_registration_is_pending_until_the_grace_elapses` now recovers after the
grace and asserts the closed gap. `scripts/target-hygiene.sh --dry-run` and
`bash -n scripts/*.sh` pass.
