# HZR 0.8.2

Released 2026-09-05. Hotfix on top of 0.8.1; see `CHANGELOG.md` for the itemized list.

## Findings that motivated the release

1. **`ACCOUNTING: DEGRADED` on a healthy daemon.** The UserPromptSubmit hook and the status line
   evaluated `live_complete` for the session while the previous command's fork-producer
   registration was still open (receipts drain on a one-second sweep). Each prompt flipped the
   session to degraded and the next rewrite flipped it back, so `accounting_degraded_seconds`
   grew by the length of every pause between commands. The 0.8.1 session that reported the
   problem had accumulated 4105 s and 13 "degraded operations" this way.
2. **Scorecard withheld everything.** One degraded interval (three daemon restarts during
   `hzr release`) made the Stop card print `Savings: unknown` although 230+ operations were
   measured.
3. **Price estimate at the wrong model.** `[billing].model` was `claude-opus-5` while the host
   session ran `claude-fable-5-1`; no host surface other than the status line names the model.
4. **Catalog aged.** `hzr-public-api-pricing-2026-08-26-v1` (max age 30 days) lacked Claude
   Fable 5.1 and GPT-6 Astra.

## Changes

- `hzr-core::accounting_coverage`: `FORK_PRODUCER_PENDING_GRACE_SECS = 600`;
  `AccountingCoverageSnapshot.pending_producer_operations`; open producer registrations without
  an operation family inside the grace are excluded from `open_intervals`,
  `open_missing_operations`, `live_complete`, `historical_complete` and lifetime totals.
- `hook_runner`: `remember_observed_model` stores `model.id` from the status line input in the
  session state; `economic_message` prices the observed model first (Claude Code harness) and
  falls back to the configured model; `scorecard_message` reports measured totals with a
  `PARTIAL:` coverage note and a lower-bound price when the session had a degraded interval.
- Catalog `data/pricing/public-api-pricing-2026-09-05-v1.json` (38 entries). Sources observed
  2026-09-05: claude.com/pricing and anthropic.com/claude/fable (Fable 5.1: $10 in, $50 out,
  $0.25 cache read, $12.50 5m cache write; 1h write = 2x input per the documented multiplier),
  developers.openai.com pricing and model pages (GPT-6 Astra $10/$1/$50, long context 2x input
  and cache, 1.5x output above 272K; GPT-5.5 $5/$0.50/$30; GPT-5.4 $2.50/$0.25/$15; GPT-5.4 mini
  $0.75/$0.075/$4.50), ai.google.dev pricing (Gemini 3.8 Flash equals 3.7 Flash through
  2026-12-31), docs.x.ai pricing (Grok 4.5 $2/$0.30/$6, long $4/$0.60/$12). DeepSeek, Mistral,
  Qwen and the existing OpenAI/Anthropic/Gemini/xAI rows were re-verified unchanged.

## Verification

Source gate (`cargo fmt`, `clippy -D warnings`, workspace tests, fork-core verification) and the
local `hzr release 0.8.2 --force` install were run on darwin-arm64. The new coverage semantics are
covered by `in_flight_producer_registration_is_pending_until_the_grace_elapses`; the scorecard and
model selection by `acceptance_gate_degraded_scorecard_reports_measured_part_as_lower_bound` and
`observed_status_line_model_prices_the_estimate_over_the_configured_default`.
