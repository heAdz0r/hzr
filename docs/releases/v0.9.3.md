# HZR 0.9.3

This patch fixes macOS index-audit failures and unnecessary approval prompts
for ordinary commands in Claude Code Auto mode.

## Doctor continues past protected directories

A registered workspace rooted at the home directory could make
`hzr doctor --reconcile-fleet --fix` walk into a protected Photos library
or another macOS TCC boundary and stop with `Operation not permitted`.

The scan now continues past permission-denied subtrees and reports their paths
as warnings. Media libraries and application bundles are skipped. An unreadable
subtree is reported as an incomplete audit, not proof that no index exists there.
Doctor defers legacy-index migration when the audit is incomplete, allowing the
rest of the report and instruction reconciliation to finish. Explicit migration
retains its completeness check.

## Ordinary commands no longer require a second HZR approval

The managed planner previously treated a missing Claude Bash allow rule as an
explicit request for approval. Even `hzr exec run 'ls'` could therefore return
`approval required` after the host had allowed the operation.

A missing rule now selects the existing managed route and leaves the host's
normal permission checks in charge. Explicit `ask` and `deny` rules, shell
ambiguity checks, and fidelity restrictions remain enforced. Auto mode is not
treated as a blanket execution grant.

## Upgrade

Run `hzr update`. If the previous post-upgrade reconciliation failed, retry
`hzr doctor --reconcile-fleet --fix` after updating.

This patch does not rewrite existing indexes, historical accounting data, or
Claude permission settings. Protected paths remain visible as warnings; no
Full Disk Access grant is required by HZR to skip them.

Release archives support Linux x64, Linux ARM64, and macOS ARM64.
