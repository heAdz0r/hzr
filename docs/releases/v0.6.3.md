# HZR 0.6.3 — efficiency you can see, trust, and price

HZR 0.6.3 completes the shift from a collection of optimizations into a measurable local
control plane.

The agent gets one efficient route. The operator gets one project identity, one index owner,
one supervised memory plane, and one ledger. At the end of the session, HZR shows how much
command output it avoided, which command families created that value, which bypasses it stopped,
and whether anything escaped. When the operator opts in, the same session can show a preliminary
public-list estimate of the potential model-input cost avoided.

That estimate is a product signal, not accounting fiction: it is visibly separate from provider
receipts and never presented as an invoice.

## The loop is now complete

```text
agent intent
    │
    ▼
managed route ──► bounded result ──► session ledger ──► token ROI
    │                                      │
    │                                      └──► opt-in public-list estimate
    │
    ├── effective replacement exists: RAW forbidden
    ├── exact bytes required: explicit fidelity capability
    └── no equivalent exists: tracked fallback, no invented credit
```

This removes the incentive gap that made a familiar native command feel easier than the
efficient command. HZR accepts the original shell intent, selects the managed route, detects
common wrappers, and names the replacement when it blocks a bypass. Avoidable RAW execution
earns zero savings credit. A clean `avoidable leakage=0` means the policy worked; it no longer
looks like “zero benefit”.

## Session value, including an optional money lens

The Stop card and `hzr stats` use the same session-attributed arithmetic for baseline,
delivered, gross avoided, regression, and estimated net avoided tokens. They also show measured
command count and privacy-safe top command families, so the most productive routes are obvious
without exposing paths, arguments, searches, or raw session IDs.

0.6.3 adds a versioned catalog of dated public API prices for popular OpenAI, Anthropic, Google,
DeepSeek, Qwen, Mistral, and xAI models. It is disabled by default. Enable only an exact
harness/provider/model/method selection:

```toml
[billing]
public_estimate_enabled = true
harness = "codex"
provider = "openai"
model = "gpt-5.6-terra"
method = "standard_short_context"
pricing_basis = "input"
# pricing_file = "/absolute/path/to/private-pricing.json"
```

Use `hzr billing catalog` to inspect the embedded evidence. Set `pricing_file` to an absolute
JSON path when your contract, gateway, region, or internal chargeback uses different rates. The
file uses the same strict, versioned schema and merges overrides by exact pricing key; HZR does
not select an approximate neighbour or perform FX conversion.

The displayed dollar figure is a **preliminary RAW estimate based on potentially avoided
session tokens and a public list price**. It is not a provider bill, subscription saving, or
guarantee that the provider would have charged those tokens. Unknown methods, missing prices,
mixed currencies, and expired entries fail closed. A receipt imported through the CLI remains
user-supplied evidence unless a trusted adapter verifies its provenance.

## Doctor checks behavior, not scenery

Previous health checks could see index artifacts without proving that semantic search could
parse the live fork configuration. 0.6.3 adds a typed runtime readiness probe. A dead semantic
path, incompatible configuration, stale index/cache state, or supervised-engine failure can no
longer borrow a healthy badge from files left on disk.

Install recovery is also scoped correctly. A completed global journal is reusable across
workspaces only after its schema, exact terminal stage receipts, and state validate. An incomplete
transaction remains bound to its owner. Current-workspace and fleet doctor now apply the same
narrow, auditable RTK waiver rules.

## One reconciliation command can restore a fleet

```bash
hzr doctor --reconcile-fleet --dry-run
hzr doctor --reconcile-fleet --migrate-legacy-indexes
```

For registered workspaces, reconciliation now refreshes stale managed blocks **and creates
missing Claude/Codex instruction surfaces and Codex project MCP pins**. Claude Code `.mcp.json`
remains an explicit project registration. Canonical-root and symlink checks confine every write.
User-authored material outside managed blocks is preserved and any surviving direct-engine
directive remains visible.

An unambiguous root `.grepai` can migrate transactionally. Ambiguous nested stores require an
explicit receipt:

```bash
hzr migrate archive-index --workspace /path/to/project \
  --source /path/to/project/nested/.grepai --dry-run
hzr migrate archive-index --workspace /path/to/project \
  --source /path/to/project/nested/.grepai --force
```

The operation records content identity, retains a backup, and refuses active writers. If a store
is recreated at the same path, HZR reports an explicit conflict and makes no mutation.

## Client limits are part of the truth model

Codex and Claude Code can use exact project-scoped MCP pins. Linked worktrees keep their own
scope without retargeting shared configuration. Claude Desktop supports one global selected
workspace, so HZR now reports every other project as `unavailable_for_this_workspace` and gives
a retarget-or-CLI action instead of pretending the singleton is a fleet-wide pin.

Codec coverage follows the same rule. `applied`, `shadow_measured`, `instructed`, and
`unavailable` describe audited behavior. A payload HZR actually transforms may receive estimated
credit. Codex and Claude do not currently expose trusted global final-response replacement, so
that path receives no economic credit.

## What remains deliberately outside the claim

- Public-list dollar estimates are preliminary and opt-in; they are not provider invoices.
- Prevented commands have no executed RAW output, so HZR reports the policy win without inventing
  counterfactual tokens.
- Output-token estimates do not prove total-session or semantic-equivalence savings.
- Windows bundles are not published in this release.
