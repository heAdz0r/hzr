# Contributor fixes: performance and scalability

Date: 2026-09-10. Scope: PRs #9/#10 and issues #4–#8/#11.
This is a code-based assessment, not a load benchmark. No latency, token-saving
or billing improvement is asserted from these changes.

## Cost changes

Explore now exits before contacting the daemon, preserving the host's own
worker concurrency. The manual reference-state remedy writes one existing
small marker and refreshes its report check. Billing selection checks are
constant-time, and one exact pricing row is added. Cargo discovery runs only
during explicit source component installation, before network/build work.
Distributed installations instead probe the existing observer binary offline.

Find collection still scales with entries visited and holds matching paths in
memory. Restoring full roots increases stored/output bytes proportional to
match count and root length. Grouping continues to share directory headers;
it must not remove path identity to save bytes. No database migration, index,
API shape or shared-service dependency is introduced.

## User-count projections

| Scope | 3 users | 100 users | 1000 users |
| --- | --- | --- | --- |
| Independent local HZR installs | Per-machine costs unchanged in kind | No new central bottleneck | No new central bottleneck |
| Many workers in one worktree | Host controls concurrency | Shared local daemon/IO may contend | Requires dedicated stress testing; unsupported capacity claim |
| Find on large trees | Depends on tree and match count | Same per-search scaling | Same per-search scaling; user count is not a proxy for tree size |
| Bundled observer install | Local identity probe | Same per-machine probe | Same per-machine probe; release artifacts carry the compile cost |

## Remaining risks

- High-cardinality find retains inherited O(matches × path length) memory use.
  A streaming redesign is outside this correctness fix.
- Cargo probes inherit the operator's environment, as the existing build did.
  This is explicit installation work, not session-start activity.
- No frontend data-flow change: only prerequisite copy changes. UI tests/build
  cover regressions; no new visual design or browser performance claim is made.
- No PRD-scale observer benchmark or API-backed model evaluation was run.
